openpilot uses C/C++ where timing and safety matter: camera and sensor daemons, the messaging layer, and the panda's safety firmware (C). The habits below keep such code predictable.

## API map

| Need | API / practice |
|---|---|
| Timing | `std::chrono::steady_clock`, `std::this_thread::sleep_until(next)` |
| Lock-free handoff | `std::atomic<size_t>` with `memory_order_acquire` / `release` |
| Avoid false sharing | `alignas(64)` on per-thread counters |
| No allocation in loops | preallocate (`std::array`, `reserve`), no `new`, no exceptions in the hot path |
| Fixed-width integers | `int32_t`, `uint64_t`; explicit casts |
| Detect races / UB | `-fsanitize=thread`, `-fsanitize=address,undefined` |
| Warnings as errors | `-Wall -Wextra -Werror`; static analysis (clang-tidy, cppcheck with MISRA addon) |

## Recipes

> [!tested] Lock-free SPSC ring buffer — `examples/driver-assist/cpp/spsc_ring.cpp`
> - **Used for:** Passing messages from one thread to another without locks or allocation.
> - **Input:** None; the program runs a producer and a consumer thread over 2 000 000 messages.
> - **Expected output:** `spsc_ring: 2000000 messages delivered in order`; the ThreadSanitizer build prints the same and no race reports.
>
> ```bash
> g++ -std=c++17 -O2 -pthread examples/driver-assist/cpp/spsc_ring.cpp -o spsc_ring && ./spsc_ring
> g++ -std=c++17 -O1 -g -fsanitize=thread -pthread examples/driver-assist/cpp/spsc_ring.cpp -o spsc_tsan && ./spsc_tsan
> ```

> [!mwe] Fixed-rate loop with deadline accounting
> - **Used for:** Running a control step at 100 Hz without drift and counting overruns.
> - **Input:** A `step()` function; the loop runs 300 iterations.
> - **Expected output:** About 3 s of wall time; `overruns` counts iterations whose start was more than one period late.
>
> ```cpp
> #include <chrono>
> #include <thread>
>
> void run(void (*step)()) {
>   using clock = std::chrono::steady_clock;          // monotonic: never jumps backwards
>   constexpr auto period = std::chrono::milliseconds(10);
>   auto next = clock::now() + period;
>   int overruns = 0;
>   for (int i = 0; i < 300; ++i) {
>     step();
>     const auto now = clock::now();
>     if (now > next + period) { ++overruns; next = now + period; }   // badly late: skip, don't burst
>     else { std::this_thread::sleep_until(next); next += period; }
>   }
>   (void)overruns;
> }
> ```

## Gotchas

- `memory_order_relaxed` everywhere "because it is faster" breaks publication of data — use release on the store that publishes and acquire on the load that consumes.
- `volatile` is not a synchronization primitive in C++.
- `std::cout` and logging in a 100 Hz loop can block — log via a queue to another thread (see the [[windows-console-server-freeze|console freeze field note]]).
- Sanitizers change timing; run them in CI, not in production.
- `std::abs(INT32_MIN)` is undefined behaviour — clamp inputs before taking magnitudes in safety code.
